00

The two backbone tables

Everything hangs off two hubs. facility is a single polymorphic table for the entire hierarchy — ORGANIZATION → PROPERTY → FLOOR → ROOM → BED — distinguished by facility_type_id. The organization is itself a facility row, and its facility_id doubles as the organization_id used by every other table. party is a generic actor; person holds human detail 1:1. Tree edges live in facility_group_member; who-occupies-what lives in facility_party.

Fig. 00 — Backbone. The whole physical tree and every membership resolve through these five tables.

Reading the hierarchy: to find a bed's room / floor / property, walk facility_group_member upward (BED → ROOM → FLOOR → PROPERTY). There are no parent columns on facility itself — the tree is entirely edge-driven and dated, so history is preserved.
